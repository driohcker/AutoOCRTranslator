# AutoOCRTranslator 需求文档

> 版本：v0.1.0  
> 状态：已确认  
> 适用范围：Windows 平台游戏实时 OCR 翻译 overlay 工具

---

## 1. 项目背景

用户在游玩 DLsite 等渠道下载的冷门日文游戏时，常遇到以下问题：

1. 游戏仅提供日文，缺乏中文支持。
2. 使用传统截屏翻译软件需要手动一次次截图、框选、翻译，操作繁琐，打断游戏体验。
3. 嵌入式翻译需要逆向分析游戏代码、修改游戏文件，技术门槛高且风险大。

因此，需要一种**轻量、便携、实时**的方案，能够自动识别游戏画面中的文字并翻译，同时将翻译结果临时缓存，避免重复翻译浪费时间。

---

## 2. 目标用户

- 主要用户：游玩无中文支持的日文/英文冷门游戏的 Windows 玩家。
- 技术水平：不一定具备编程或逆向工程能力，希望工具开箱即用。
- 使用场景：全屏或窗口化运行游戏时，希望在画面上直接看到译文。

---

## 3. 用户场景（Use Cases）

### UC-01：启动并选择游戏窗口
- 用户启动 AutoOCRTranslator。
- 工具列出当前所有可见窗口。
- 用户选择要翻译的游戏窗口。
- 工具开始实时监控该窗口。

### UC-02：实时翻译游戏画面文字
- 工具按设定间隔自动截取游戏画面。
- OCR 识别画面中的文字块及位置。
- 翻译模块将文字翻译为中文。
- 译文以覆盖层形式显示在原文字位置上方。

### UC-03：缓存避免重复翻译
- 当画面中某段文字此前已翻译过时，工具从缓存中读取译文，不再调用翻译 API。
- 缓存可设置有效期，过期后重新翻译。

### UC-04：调整显示样式
- 用户可在设置界面调整译文字体、字号、颜色、背景透明度等。
- 修改后实时生效。

### UC-05：暂停/继续翻译
- 用户可通过热键或按钮暂停翻译，避免在不需要时占用资源。
- 再次操作可恢复翻译。

### UC-06：配置翻译服务
- 用户可选择翻译服务提供商（免费/商业 API）。
- 用户可填写 API Key 等凭证。
- 配置持久化保存。

## 4. 功能需求

### FR-01：窗口捕获
- **FR-01.1**：工具应能枚举当前系统中所有可见窗口及其标题。
- **FR-01.2**：工具应支持按窗口标题关键词自动匹配目标窗口。
- **FR-01.3**：工具应支持用户手动从列表中选择目标窗口。
- **FR-01.4**：工具应能持续捕获目标窗口的客户区画面。
- **FR-01.5**：当目标窗口最小化、关闭或失去焦点时，工具应能检测并处理。

### FR-02：OCR 文字识别
- **FR-02.1**：工具应能识别截图中的文字内容。
- **FR-02.2**：工具应能输出每个文字块的坐标（边界框）。
- **FR-02.3**：工具应支持日文（重点）、简体中文、繁体中文、英文。
- **FR-02.4**：工具应能过滤低置信度识别结果。
- **FR-02.5**：OCR 语言应在配置中可调整。

### FR-03：翻译
- **FR-03.1**：工具应能将识别到的文字翻译为目标语言（默认中文）。
- **FR-03.2**：工具应支持至少一种免费翻译方案作为默认选项。
- **FR-03.3**：工具应预留商业翻译 API（DeepL、腾讯云、阿里云等）扩展接口。
- **FR-03.4**：翻译源语言和目标语言应在配置中可调整。
- **FR-03.5**：翻译失败时应给出友好提示，不影响后续帧处理。

### FR-04：翻译缓存
- **FR-04.1**：工具应将翻译结果缓存到本地数据库。
- **FR-04.2**：缓存键应包含原文文本、源语言、目标语言。
- **FR-04.3**：再次遇到相同原文时，应优先从缓存读取译文。
- **FR-04.4**：缓存应支持设置有效期（TTL），过期自动失效。
- **FR-04.5**：用户应可清空缓存，并可针对不同游戏或应用作区分，可选择性清空缓存。

### FR-05：覆盖层显示
- **FR-05.1**：工具应在游戏画面上方显示译文。
- **FR-05.2**：覆盖层应为无边框、置顶、透明窗口。
- **FR-05.3**：覆盖层应支持点击穿透，不阻塞游戏操作。
- **FR-05.4**：译文应显示在原文字所在位置附近。
- **FR-05.5**：覆盖层应跟随目标窗口移动和尺寸变化实时更新。
- **FR-05.6**：译文字体、字号、颜色、背景色、最大宽度应在配置中可调整。

### FR-06：配置管理
- **FR-06.1**：工具应使用 YAML 文件保存配置。
- **FR-06.2**：配置应包括窗口捕获、OCR、翻译、缓存、覆盖层等参数。
- **FR-06.3**：配置应在程序启动时加载，退出时保存。

### FR-07：图形设置界面
- **FR-07.1**：工具应提供设置窗口，允许用户修改所有配置项。
- **FR-07.2**：设置窗口应支持测试翻译 API 连通性。
- **FR-07.3**：设置修改后应即时生效或下次启动生效（视参数而定）。

### FR-08：主控制
- **FR-08.1**：工具应提供启动/暂停/继续翻译的控制。
- **FR-08.2**：工具应支持全局热键（如 F9 暂停/继续）。
- **FR-08.3**：工具应在系统托盘运行，提供右键菜单。

### FR-09：日志与错误处理
- **FR-09.1**：工具应记录运行日志，便于排查问题。
- **FR-09.2**：任何模块出错都不应导致整个程序崩溃。
- **FR-09.3**：关键错误应以弹窗或托盘提示方式告知用户。

## 5. 非功能需求

### NFR-01：性能
- **NFR-01.1**：截图+OCR+翻译+显示的全流程延迟应控制在可接受范围内（目标 < 2 秒/帧）。
- **NFR-01.2**：CPU 占用应尽可能低，避免影响游戏流畅度。
- **NFR-01.3**：截图间隔应可配置（默认 1000ms）。

### NFR-02：兼容性
- **NFR-02.1**：工具应支持 Windows 10/11。
- **NFR-02.2**：工具应支持窗口化、无边框窗口化和全屏游戏（全屏截屏可能存在限制，需测试）。
- **NFR-02.3**：工具应支持常见 2D/视觉小说/RPG 等游戏类型。

### NFR-03：易用性
- **NFR-03.1**：普通用户无需修改代码即可使用基础功能。
- **NFR-03.2**：配置界面应清晰直观。
- **NFR-03.3**：工具应提供默认配置，开箱即用。

### NFR-04：稳定性
- **NFR-04.1**：工具应能长时间稳定运行（数小时级别）。
- **NFR-04.2**：游戏窗口关闭或切换后，工具应自动恢复或等待用户重新选择。

### NFR-05：可扩展性
- **NFR-05.1**：翻译服务应支持插件式扩展。
- **NFR-05.2**：OCR 引擎应预留替换接口。
- **NFR-05.3**：配置结构应便于后续增加新参数。

### NFR-06：安全性
- **NFR-06.1**：API Key 等敏感信息应仅保存在本地配置文件中，不对外传输。
- **NFR-06.2**：缓存数据库仅存储翻译文本，不收集用户其他信息。

---

## 6. 约束条件

- **平台约束**：仅支持 Windows 系统。
- **技术约束**：使用 Python 生态开发，便于快速迭代和集成开源 OCR/翻译库。
- **法律约束**：用户需自行提供合法翻译 API 凭证，工具本身不提供翻译服务。
- **性能约束**：免费翻译 API 可能存在调用频率限制，需配合缓存机制使用。

---

## 7. 术语表

| 术语 | 说明 |
|------|------|
| OCR | Optical Character Recognition，光学字符识别 |
| Overlay | 覆盖层，指悬浮在游戏画面上方的透明窗口 |
| TTL | Time To Live，缓存有效期 |
| API Key | 翻译服务提供商的访问密钥 |
| 客户区 | 窗口中除去标题栏和边框的内容区域 |
| DLsite | 日本数字同人作品销售平台 |

---

## 8. 验收标准

- [ ] 能正确选择并捕获目标游戏窗口画面。
- [ ] 能识别游戏画面中日文/中文文字及位置。
- [ ] 能将识别出的日文翻译为中文并显示在画面上。
- [ ] 相同文字重复出现时，能命中缓存，不重复调用 API。
- [ ] 用户可通过 GUI 修改配置并生效。
- [ ] 程序运行稳定，主要错误有日志和提示。
- [ ] 可打包为独立 exe 运行。
